# RepoPilot-R 重要代码逐行解析

本文按最终源码行号解释主链路，目标不是复述文件名，而是说明每个关键分支为什么存在。推荐按“状态约束 → 有界循环 → 权限网关 → 持久化 → 恢复 → 验收 → 证据”阅读。每个范围都可在源码中直接定位。

## 1. 状态机：成功只能沿显式边到达

范围：`src/repopilot/domain/state_machine.py:10-76`

- 10 行用只读 `Mapping` 声明唯一转换表；11—65 行枚举每个状态的目标集合。
- 12—25 行规定任务必须经历索引与规划；规划才能进入执行或审批等待。
- 27—46 行把执行、测试、审查拆开，所以模型返回 `final` 不等于成功。
- 48—60 行定义恢复态和审批态的出口；审批通过只能回到执行。
- 62—64 行给成功、失败、取消三个终态空集合，终态不能被后续调用偷偷改写。
- 69—76 行只暴露布尔查询和不可变集合，调用方不能修改全局规则。

## 2. Agent 循环：预算由宿主掌握

范围：`src/repopilot/agent/loop.py:56-124`

- 59—72 行注入最大步数、上下文字符数、重复调用次数和墙钟预算，并拒绝非正配置。
- 74—90 行使用单调时钟计算本轮剩余时间；预算耗尽时抛出领域异常。
- 92—95 行先把恢复出的历史调用计入重复指纹，重启不会清空循环保护。
- 96—102 行在模型调用前后检查取消与时间，所以过期的模型动作不能继续触发工具。
- 103—105 行接受结构化 `FINAL`，但返回的是 `FinalAnswer`，后续仍要确定性验收。
- 106—113 行用“工具名 + 参数摘要”统计等价调用，阻止模型换 operation ID 绕过重复限制。
- 114—120 行把剩余秒数下传到统一网关，并在工具返回后再次检查总预算。
- 121—123 行把请求/结果成对写回上下文；遇到 `APPROVAL_REQUIRED` 立即结束本轮，不给模型旁路审批的第二次机会。

## 3. 上下文压缩：请求和结果永不拆对

范围：`src/repopilot/agent/actions.py:77-130`

- 77—92 行让 Issue、约束、成对 exchange 和压缩次数组成不可变上下文。
- 94—100 行先验证最小预算，再确定只压缩较老 exchange，最近两组完整保留。
- 101—110 行第一轮把旧结果替换为带 120 字预览的摘要。
- 111—116 行第二轮去掉预览；连最小元数据都放不下时明确失败，不静默删因果关系。
- 118—130 行用原始结果 SHA-256、`compacted` 和 `truncated` 构造新结果，并保留原请求身份。

## 4. 路径边界：解析后证明包含，而不是比较字符串

范围：`src/repopilot/tools/policy.py:17-66`

- 18—22 行先拒绝 NUL 和绝对路径。
- 23—24 行分别解析 worktree 根和目标，`..` 与符号链接都会在这里归一化。
- 25—28 行用 `relative_to(root)` 做包含性证明，任何越界都转成 `PathPolicyError`。
- 30 行只返回已验证路径，文件工具不再使用未经规范化的输入。
- 33—46 行从 unified diff 文件头提取稳定改动路径；49—66 行按 `allowed_paths` glob 和 `max_changed_files` 返回宿主侧范围违规。

`/tmp/repo-evil` 不会因为字符串前缀像 `/tmp/repo` 而被误放行；指向仓库外的 symlink 也会得到真实目标后被拒绝。

## 5. 权限策略：ALLOW、ASK、DENY 三分流

范围：`src/repopilot/tools/policy.py:69-210`

- 93—106 行把命令、MCP、允许路径和最大文件数作为宿主配置，不从 prompt 推断。
- 108—136 行只为已知工具进入专属规则；patch 必须先有可解析路径，再过 worktree 包含、glob 与文件数校验。
- 137—151 行要求 MCP 工具同时具有 `mcp__` 命名空间和操作员精确 allowlist，最后是 fail-closed 默认分支。
- 153—161 行再次对读/搜路径做包含校验。
- 163—175 行要求命令是非空 JSON 字符串数组，不接受 shell 字符串。
- 176—193 行按真实可执行文件封锁 shell、网络命令、破坏性 Git、内联 Python 和 shell 标记。
- 194—198 行只有完整 argv 元组命中 allowlist 才直接运行，其余非破坏性命令进入人工审批。

## 6. 安全网关：先授权和 claim，再产生副作用

范围：`src/repopilot/tools/gateway.py:47-123`

- 55—57 行先按 `task_id + operation_id` 查已提交结果；命中就重放，不调用工具。
- 59—69 行执行策略；拒绝也生成可审计、可持久化的 `ToolResult`。
- 70—93 行处理 `ASK`。只有同时匹配操作 ID 与参数摘要的批准才有效；否则审计事件保存脱敏参数，精确请求交给 store 加密保存，然后返回暂停信号。
- 95—102 行在真正调用工具前，通过 store 原子 claim 操作身份并写 `tool.started`。
- 103—109 行处理 claim 已存在：有结果则重放，只有意图没有结果则抛 `OperationInProgress`，避免未知副作用被重复执行。
- 110—123 行 claim 成功后才查注册表调用工具，并把任务剩余秒数传给适配器；可预期异常变成失败结果，最后统一提交。

范围：`src/repopilot/tools/gateway.py:125-227`

- 125—142 行先脱敏输出和错误，再把结果与终结事件交给 SQLite 原子提交。
- 144—159 行重放只追加 `tool.replayed`，返回原结果。
- 161—170 行审批同时比较 `operation_id` 与 `arguments_digest`，修改参数会让旧批准失效。
- 172—175 行递归脱敏并恢复 JSON 类型约束。
- 177—207 行事件只保存脱敏参数、摘要、状态、耗时和截断标识。
- 209—227 行构造副作用之前的 `tool.started` 意图；它是未知结局 fail-stop 的持久证据。

## 7. SQLite：加密审批、操作 claim 与原子结果

范围：`src/repopilot/infrastructure/sqlite.py:52-144`

- 52—56 行让数据库与同名本机密钥成为一个持久边界。
- 59—81 行用独占创建和 `0600` 权限生成 Fernet 密钥；已有密钥权限过宽或内容损坏时初始化即停止，密钥丢失后遗留 pending 也会因无法解密而停止。
- 99—144 行启用 WAL，并分别建立快照、事件、已完成操作、执行 claim 与加密待审批请求表；公开事件和精确审批参数不混存。

范围：`src/repopilot/infrastructure/sqlite.py:214-369`

- 214—236 行按事件顺序重建首次终结的请求/结果对；恢复的模型上下文不是空白新会话。
- 238—282 行把排除计算字段后的精确 `ToolRequest` 加密，并与脱敏审批事件、快照在同一个写事务中保存；相同操作 ID 换参数会冲突。
- 284—307 行解密后重新计算参数摘要，并同时核对 operation ID 与数据库摘要；密钥或密文异常不会降级成脱敏参数执行。
- 309—337 行以 `BEGIN IMMEDIATE` 查询已完成操作和未完成 claim；相同身份存在时不抢第二次执行权，摘要变化则拒绝复用。
- 338—364 行再次绑定 pending 摘要，在同一事务中插入 claim、删除精确 pending、写 `tool.started` 并推进快照。

范围：`src/repopilot/infrastructure/sqlite.py:371-441`

- 371—380 行提交前验证 request/result 的操作与工具身份完全相同。
- 381—402 行处理已经提交的结果：摘要一致时只追加 replay 事件并推进快照，摘要变化则抛幂等冲突。
- 404—435 行校验 claim，把脱敏结果插入 operations、删除 claim，并把终结事件与快照一起提交。
- 437—441 行任意异常回滚，连接始终关闭。

范围：`src/repopilot/infrastructure/sqlite.py:443-505`

- 443—450 行所有按 ID 读取都统一执行“不存在即失败”的快照反序列化。
- 452—485 行检查 expected sequence、事件任务身份、连续序号、来源状态与合法状态转换，再从事件生成新快照。
- 488—505 行把事件唯一约束冲突转换成领域并发错误，并集中写回最终快照 JSON。

这里刻意区分“可以重放的已知结果”和“不能猜测的未知结局”，没有把 exactly-once 当作一句口号。

## 8. Git worktree：崩溃后可以认领原工作树

范围：`src/repopilot/infrastructure/git.py:39-95`

- 40—43 行要求输入正好是 Git 顶层目录。
- 44—48 行清洗任务 ID，确定唯一分支和工作树路径。
- 49—50 行发现目标已存在时进入验证式 adoption，而不是直接报错或覆盖目录。
- 51—64 行首次运行通过 `git worktree add -b` 从当前 HEAD 建立隔离分支。
- 66—90 行检查现有目录的 Git 顶层、当前分支和 common Git dir；三项完全匹配才认领同一任务边界。
- 92—95 行统一解析相对或绝对 common Git dir，避免只按字符串比较仓库身份。

## 9. 代码地图：结构信息和检索都受预算约束

范围：`src/repopilot/tools/repository.py:89-137`

- 89—95 行校验字符预算和仓库根。
- 96—106 行读取经过包含性验证的文件；Python 使用 Tree-sitter 提取符号、AST 提取 import。
- 108—113 行从 Issue 提取词项，再用 ripgrep 或词法回退收集相关片段。
- 114—135 行稳定排序语言、测试文件、符号、依赖与能力标志，消除文件系统遍历差异。
- 137 行统一裁剪到上下文预算。发现阶段也拒绝指向仓库外的 symlink，不让索引器绕过工具路径策略。

## 10. 恢复编排：从快照和操作历史继续

范围：`src/repopilot/application/orchestrator.py:98-185`

- 105—107 行每次 run 先重读快照；终态调用直接返回。
- 108—118 行按当前状态进入准备、执行、等待审批、测试或审查，因此每个阶段都可重入。
- 119—122 行让故障注入、幂等冲突和未完成 claim 保持各自语义；并发 claim 不会被误写成任务失败。
- 123—134 行其他异常被脱敏后转成 `task.failed`，不会只留在控制台。
- 136—185 行准备每个阶段前后都检查从 `created_at` 计算的持久截止时间，再创建 worktree、建图和持久化计划。

范围：`src/repopilot/application/orchestrator.py:187-271`

- 193—197 行构造任务专属网关，测试可以在已提交操作后包一层故障注入。
- 198—205 行批准恢复后由宿主先执行持久化的 pending 请求，不要求 runtime 再次生成相同动作。
- 206—225 行从 SQLite 还原成对历史、扣除已消费步数，并把任务总墙钟的剩余值交给 Agent loop。
- 226—250 行把审批信号转换为 `WAITING_APPROVAL`；没有审批时才进入测试。
- 252—271 行从批准事件取 operation ID 与摘要，再向 store 索取已解密的精确请求；请求缺失或摘要不一致都安全停止，不拿审计中的脱敏参数替代执行。

## 11. 测试和非空 diff 决定成功

范围：`src/repopilot/application/orchestrator.py:273-394`

- 273—301 行由宿主构造稳定的 `verify-{task_id}` 操作，按任务剩余墙钟重跑创建时的精确测试 argv；失败直接进入失败终态。
- 303—325 行随后用稳定 `diff-{task_id}` 读取完整工作树差异，并继续受同一总截止时间约束。
- 326—334 行显式拒绝空 diff，避免“什么都没改但模型说完成”进入 `SUCCEEDED`。
- 335—357 行要求 diff 工具返回结构化改动路径，并在最终审查再次执行允许路径与最大文件数规则。
- 358—367 行只在测试、非空 diff 和范围检查都成功后写审查摘要并进入成功。
- 369—386 行所有状态事件在保存前统一脱敏，并用 expected sequence 原子前进。
- 388—394 行始终用持久化 `created_at` 计算剩余墙钟；恢复服务不会得到一份新预算。

## 12. 证据四件套：审计脱敏，patch 保真

范围：`src/repopilot/infrastructure/artifacts.py:45-178`

- 45—53 行要求任务、验证操作和 diff 操作都已成功。
- 54—63 行确定任务目录并生成 patch、测试报告、JSONL 轨迹和 PR 草稿内容。
- 65—75 行四个文件都走同一原子写入路径。
- 77—107 行返回每份工件的 SHA-256 与元数据；patch 明确标记 `access-controlled-exact`。
- 115—122 行读取审计 diff 中的原始摘要并要求任务仍有工作树。
- 123—138 行复用 `GitDiffTool` 重新取得包含 staged、unstaged、untracked 的完整差异，拒绝失败、超时、截断或结构缺失。
- 139—144 行同时比较精确 diff 的 SHA-256 与结构化路径；任一不一致都拒绝生成证据包。
- 171—178 行只接受全为字符串的审查路径并稳定排序，PR 草稿与 patch 元数据不靠脆弱的正文正则猜路径。

数据库中的 diff 可脱敏供 API 与轨迹展示，本地 `change.patch` 则保留可应用字节。两种披露等级由哈希绑定，既不把秘密正文暴露到页面，也不生成被 `[REDACTED]` 破坏的补丁。

## 13. 文件读取与完整 diff：输入、时间和变更类别都设硬边界

范围：`src/repopilot/tools/builtin.py:56-105`

- 62—70 行校验路径和剩余预算；预算已耗尽时不打开文件。
- 71—92 行使用 `O_NOFOLLOW`、`fstat` 和 regular-file 检查，只读取 `max_bytes + 1`，因此 1 GiB 稀疏文件也不会先整体载入内存，描述符始终关闭。
- 93—105 行拒绝二进制内容，只返回有界文本、真实文件大小与截断标记。

范围：`src/repopilot/tools/builtin.py:282-397`

- 295—318 行用 `git diff HEAD` 覆盖已暂存与未暂存 tracked 变更，并用 NUL 分隔命令独立取得 tracked/untracked 路径。
- 320—353 行逐个把未跟踪文件生成为 `/dev/null` 到新文件的二进制安全 diff，所有片段共享 256 KB 总上限。
- 354—366 行任何失败、超时或超限都返回失败结果；成功才保存完整 diff、原始摘要和稳定路径列表。
- 368—397 行让每个 Git 子进程共享同一 15 秒总预算，并拒绝任何截断或异常退出，不能拿半份证据继续审查。

## 14. 进程执行：有界流式读取并终止整组

范围：`src/repopilot/infrastructure/process.py:34-144`

- 43—61 行验证 argv、超时、输出上限和环境 allowlist，并禁止 Python 测试生成未声明的 bytecode 文件污染最终 diff。
- 63—81 行给 stdout/stderr 共享一个总字节预算，两个 drain 线程边读边截断，不把无限输出全部积存在内存。
- 83—92 行使用参数数组、`shell=False` 和新 session 启动进程。
- 93—117 行并行排空两个管道，写入可选 stdin，并在超时时进入进程组清理。
- 118—127 行只返回有界文本、退出码、耗时、超时与截断证据。
- 129—144 行先给整个进程组 `SIGTERM`，短暂等待后无条件尝试 `SIGKILL`；即使父进程先退出，忽略 TERM 的子孙进程也不能继续留在后台。

## 15. 评估器：用隐藏测试和 Git 事实评分

范围：`src/repopilot/evaluation/runner.py:35-156`

- 35—44 行要求新工作区，逐 case 执行并落盘 JSON/Markdown。
- 46—70 行创建真实仓库；故障 case 在指定操作后中断，重建 service 再 resume。
- 72—83 行生成证据，并在隐藏测试安装前固化 Agent 的完整改动。
- 84—118 行调用独立隐藏验收器，结合终态、完整差异、隐藏测试与精确路径范围评分，记录补丁摘要、恢复和耗时。
- 120—156 行复用生产策略构造服务，精确限制允许命令、改动路径和文件数。

新增 `evaluation/verification.py` 要求预期隐藏测试在 JUnit 中实际完成；零退出码本身不构成通过。`evaluation/paired.py` 提供 RAG 开关实验、完整失败分母与事后人工备注，`evaluation/retrieval.py` 对真实词法工具评分，详细口径见 [对照评估](PAIRED_EVALUATION.md)。

## 16. 在线模型和 MCP 都只是适配器

范围：`src/repopilot/agent/openai_runtime.py:48-121`

- 51—62 行把模型名、工具目录、SDK importer 和决策 runner 都做成依赖。
- 64—81 行只把 SDK 决策转换为领域 `AgentAction`，不执行工具。
- 83—100 行再次用 Pydantic 校验 tool/final 互斥形状。
- 102—121 行把 Issue、约束、历史长度、工具名与参数规范化后计算稳定 operation ID。

范围：`src/repopilot/infrastructure/mcp.py:38-200`

- 41—55 行把服务器与远端工具规范成 `mcp__server__tool`，保留来源。
- 57—71 行发现 schema 与描述，但不自动加入 allowlist。
- 73—114 行执行前核对精确名称和剩余时间；远端响应仍包装成领域结果，超时返回明确失败。
- 116—143 行在 daemon 线程中包住同步或异步 transport，并用有界队列等待截止时间；本地调用不会被永远卡住。
- 145—182 行拒绝歧义名称、处理同步/异步边界，并把远端内容重新校验为领域 JSON。
- 184—200 行把所有远端结局统一包装成带操作身份、状态、错误与耗时的 `ToolResult`。

线程超时只能保证本地等待有界，不能强制取消任意第三方 transport。远端副作用仍需服务端幂等键、取消协议或补偿流程；这一限制没有被包装成“远端调用已终止”。

因此接 GPT-5.6、其他模型或新的 MCP server 只替换决策/工具来源，不会替换权限、持久化、恢复和验收主链路。
