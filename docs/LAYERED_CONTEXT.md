# 结构化任务状态与分层上下文（Demo）

本版将运行上下文分为三部分：固定的任务目标与宿主规则、从工具历史重建的工作状态、配对的工具请求和结果。它不增加模型写入权限，不改变审批、路径检查或验收。完整操作记录仍存于原任务数据库，工作状态是派生视图。

## 工作状态保留什么

- 当前处理阶段及最近可能产生副作用的操作位置；这不是模型自报的完成状态。
- 最近 8 条非文件读取证据和最近 4 条文件读取证据，避免大量搜索/读取淹没较早的 RAG 与记忆引用。
- 每次 RAG / 记忆检索最多保留前 2 个命中的路径、引用、摘要、记忆 ID、有效状态及 240 字符摘录。其余内容仍通过原操作 ID 回读。
- 最近最多 8 组读取记录：路径、范围、页面内容 SHA-256、原操作 ID、相同参数读取次数。页面摘要不冒充整文件哈希。
- 最近失败/拒绝操作标识、命令退出码与补丁摘要。历史失败保守保留，不能据此认定当前故障一定未修复；退出码也不等于宿主最终验收。

这些字段随旧结果压缩一起保留，多次压缩不丢原摘要；预算极小时，可在去掉预览后舍弃较旧的可选读取记录，保留原始摘要并通过 context_read 恢复；恢复任务时从数据库原始历史重建。引用、摘录、记忆均带历史及不可信标记，仅放在普通上下文中，不提升为系统规则。摘录不一定包含全部关键语义，超出数量/长度上限的证据仍需要回读。

## 重复读取与失效

系统提示要求先查看工作状态已有证据，再决定是否需要重复读取或 context_read。读取记录提供明确的操作标识和范围；不会自动代替模型作语义判断，也不会跳过真实工具执行。

任何不在固定只读集合中的工具调用都会清空可复用读取集合，包括失败的命令/补丁和未知 MCP 工具，因为它们可能已经产生部分副作用。所有引用继续保留为历史证据。外部进程仍可能修改文件，因此记录不能保证当前新鲜度；编辑前必须检查当前文件。未扩大原重复调用上限，也未扩大只读子代理权限。

## token 预算与输出预留

配置放在操作者指定的 TOML 的 `[provider]` 中。例如对接受 `max_tokens` 的现有 DeepSeek 兼容配置：

```toml
[provider]
protocol = "openai"
base_url = "https://api.deepseek.com"
model = "deepseek-flash"
api_key_env = "DEEPSEEK_API_KEY"
context_window_tokens = 32768
output_reserve_tokens = 4096

[provider.request_options]
max_tokens = 4096
thinking = { type = "disabled" }
```

32768 是演示用的操作者预算，不是对供应商模型最大窗口的声明。发送前检查：估算输入 + 输出预留 ≤ 配置窗口，并同时满足任务原有字符上限。超限压缩旧结果，仍装不下则停止，直接调用 HTTPRuntime 也不能绕过 token 预留检查。

`utf8_bytes_v1` 估算器使用完整序列化请求 UTF-8 字节数加 256 的固定余量，包括工具目录、规则、状态和历史。这是偏保守的跨模型估算，不是厂商 tokenizer、不是严格上界，也不是计费用量；可能提前拒绝本可容纳的请求，模型特殊编码仍可能导致估计误差。Demo 未新增 tokenizer 依赖。

输出预留同步写入 API 输出上限。已有 request_options 若指定 `max_completion_tokens`，则保留该参数；Anthropic 使用 `max_tokens`。不能同时指定两种参数，输出上限与显式预留不能矛盾。接受哪一种参数取决于目标模型，配置必须与其接口匹配。

未配置窗口/预留且未指定输出上限的 OpenAI 兼容配置保留旧请求行为，不自动注入 max_tokens，也不声称已启用输出预留。Anthropic 原有默认 4096 上限保留。未指定总窗口时，不声称进行模型总 token 窗口检查。

## 实际用量记录

生产主任务每个收到并解析的模型响应产生 `model.usage` 事件，包含发送前估算和供应商实际 input/output token 数。OpenAI 兼容协议读取 prompt_tokens/completion_tokens；Anthropic 读取 input_tokens/output_tokens，并单独记录 cache_read_input_tokens/cache_creation_input_tokens。字段按供应商原值记录，不能把不同缓存口径混为同一计费公式。

只提取非负整数，不保存响应正文、密钥或任意 usage 附加内容。未提供或无效字段记为 null。收到响应但动作无效时仍保留已知用量；网络中断、无法解析的响应可能发生未知消耗，本版不能恢复这些用量。任务恢复继续追加事件，避免仅靠当前进程内累计数。后台分析子代理目前不持久化此任务级用量账本。

可通过原 `forgepilot inspect TASK_ID --workspace WORKSPACE --json` 或事件 API 查看 model.usage；本版没有新增图表或美元费用估算。

## 对照实验与复现

[结构化结果](CONTEXT_COMPARISON.json)含 6 个确定性场景：先检索代码/记忆并读取文件，再加入不同长度的无关搜索结果，均以 AgentContext 的 30,000 字符预算压缩。增强组保留证据字段；对照组从相同压缩历史移除这些字段，模拟旧摘要/短预览表示。这是表示消融，不是旧 HTTP harness 的完全回放。

6 个场景均从 0/3 必需字段可用变为 3/3；按“缺一个字段则补读一次”的固定策略，需要恢复的字段从 3 变为 0。该计数是固定策略推导，不是真实 LLM 发出的请求次数，也不能宣传为真实重复读取率下降。报告预算只针对序列化 AgentContext；生产 HTTP 的额外状态、系统提示与工具目录另受完整请求检查。

复现（项目根目录，先安装项目依赖）：

```bash
PYTHONPATH=src python -c 'import json; from repopilot.evaluation.context import compare_context; print(json.dumps(compare_context(), indent=2))'
```

真实 HTTP 合约集成另外覆盖工具调用、补丁、验收、审批恢复和用量事件持久化。未在本轮调用新的 DeepSeek API，尚不能声称解决之前所有 48k 压力失败或证明模型修复率提升。

本轮验证：后端 436 passed / 5 skipped，覆盖率（含分支）88.83%；Ruff、mypy、前端 12 项测试、类型检查与构建通过。跳过项涉及既有 MySQL 环境条件与 SQLite 行锁适用性。
