# ForgePilot：不依赖本机的部署方案

状态：设计方案，尚未购买云资源、上传仓库、配置公网域名或部署。依据 2026-10-23 本机端到端验收和当前代码审计；本机通过不等于 Linux/公网部署已经通过。

## 推荐方案

先做**单用户、单服务器、受身份认证保护的工作台**。浏览器访问 HTTPS 域名；云服务器运行前端、API、后台 worker、Git 工作区和 MySQL。Mac 关机后任务仍在云端执行。不要把运行在 Mac 的隧道当作云部署。

```text
你的浏览器 → HTTPS 域名 + 身份认证 → 云服务器上的隧道/反向代理
                                      ↓
                              ForgePilot API / 单协调器
                                ↓             ↓
                          私网 MySQL      后台模型 worker → DeepSeek API
                                              ↓
                                    受隔离的仓库执行环境
```

建议初始资源为 Linux 虚拟机 4 vCPU / 8 GB RAM / 80 GB SSD，无需 GPU。这个数字是低并发开发工作台的容量起点，不是已测性能保证；并发初始限制为 1。费用由云厂商、地区、磁盘/备份、域名及模型调用量决定，选定地区后再核算，不在此给未经核实的月费。

数据库与工作区都放云端持久卷。MySQL 只开放给应用的私网身份，不开放公网 3306；用独立业务账号和数据库，测试库与业务库分开。保留 MySQL 事件存储、SQLite 作业队列与审批加密密钥；**当前队列不是分布式调度器，不可直接横向增加多个协调器**。备份必须把数据库、队列、工件、工作区及审批密钥作为一致的恢复集合，不能只备份 MySQL。

## 上线前必须补齐的差距

| 当前状态 | 必须完成的改造/验证 |
| --- | --- |
| CLI 控制服务绑定 loopback，Host/Origin 只允许本机 | 配置精确的外部 HTTPS 域名和可信代理；不设通配 CORS，不接受任意转发头 |
| 控制 token 是 CSRF 防护，不是登录认证 | 用身份网关限制本人账号并启用 MFA；保护所有控制、工件和 SSE 路径；回源校验受众/签名或限定可信代理通道 |
| TUI 只允许本机 HTTP 地址 | 第一阶段用浏览器；远程 TUI 要另做 HTTPS、身份认证和凭据存储，不能简单删掉 URL 检查 |
| worktree / argv / 环境过滤属于应用约束 | 运行测试代码需要 OS 级执行隔离；不能称作已支持恶意仓库的安全沙箱 |
| Mac/Python 3.13/MySQL 9.6 已验证 | Linux 干净安装、锁定依赖和选定 MySQL 版本重新跑完整测试；不能直接复制 Mac 的虚拟环境 |
| 本机提示输入 Key | 云端使用 Secret Manager 或服务器受限凭据文件注入服务，不进源码、镜像层、浏览器或任务输出 |

执行隔离的最低要求：把持有模型/数据库凭据的控制进程与运行候选测试的进程分开；每个任务仅挂载自己的工作区，外部验收与基础工具只读；禁止挂载宿主 Docker socket、凭据目录、其他任务目录。默认无外网、无宿主网络，非 root、去 capabilities、限制 CPU/内存/PID/时间，取消任务能终止其全部子进程。依赖下载如有必要应在受控准备阶段完成。Rootless 容器能降低权限风险，但不代表可安全托管任意对抗性代码；公开多租户需更强隔离和专门安全审查。Docker 官方说明见 [Rootless mode](https://docs.docker.com/engine/security/rootless/)。

## 访问入口的选择

推荐身份网关 + 从**云服务器**发起的 Tunnel。公开 HTTPS 域名指向云端工作台；Mac 不承担回源或 worker。Cloudflare Access 的自托管应用可作为身份入口，但必须设置明确的允许账号/身份策略；不能仅有 Tunnel 没有 Access。官方配置见 [保护 Web 应用](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/)。这只是推荐组合，尚未在本项目实施或验证。

服务器内部继续使用 `127.0.0.1` 或私网地址是正确的安全设计；你对外看到的是域名，且不依赖本机。目标不是从所有配置里消灭 `127.0.0.1`，而是把运行责任迁到云端。

简历展示入口与真实工作台分离：展示页只提供脱敏任务轨迹、补丁、测试结果及离线演示；不允许匿名用户提交任意仓库、执行命令或消耗你的 API 额度。

## 实施顺序与验收门槛

1. 选择云厂商/地区、域名和身份账号，确认预算及备份位置。当前未授权开通付费资源。
2. 在私网/管理通道完成 Linux 安装与单实例运行。重建虚拟环境，安装 Git/rg；使用锁定依赖，不复制 `.venv`、本机路径或现有密码。
3. 配置云端新 Key 与最小权限 MySQL，持久卷、日志脱敏、模型消费上限及备份。MySQL 访问控制参考 [官方安全指南](https://dev.mysql.com/doc/refman/8.4/en/security-guidelines.html)。版本迁移需实测，不直接复用数据目录。
4. 完成上表中的认证、代理与执行隔离改造，增加拒绝路径测试；再启用 HTTPS 域名访问。保持现有精确审批/验收规则，以及本次 E2E 使用的 40 步/900 秒预算，不为上线放宽限制；这不是全局默认值（默认仍为 24 步/300 秒）。
5. 云端复跑本次分页任务和完整回归：固定基线、外部验收哈希、真实 DeepSeek、真实 MySQL、工件哈希。记录多轮/人工反馈，不包装为零干预成功。
6. 从另一设备提交任务，关闭 Mac 验证仍完成；服务器重启后能查询历史，任务恢复遵守剩余预算；取消后无遗留执行进程。
7. 未登录请求不得读取任何任务/工件或触发写操作；伪造 Origin/Host/代理头被拒；任务不能读取云端 secrets、其他仓库或连接数据库；公网上无法直连 MySQL/API 回源；完成一次真实备份恢复演练。

在上述门槛通过前，只定位为个人可信仓库原型，不对外宣称多租户生产服务。整个方案不需要 Kubernetes；只有单机并发/恢复需求被证据证明不足时，再设计分布式队列与 worker 调度。

## 本机继续使用

项目源码已经更新，但当前用户启动的 UI 父进程仍可能缓存旧模块。后续日常使用前，待所有任务结束，在原终端正常停止工作台，再运行原 `start-live.command`，重新隐藏输入 DeepSeek Key。不要在聊天中发送密钥。云端尚未部署，因此目前关闭 Mac 仍会停止本机服务。
