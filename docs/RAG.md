# 仓库 RAG（Demo）

已实现基于 **SQLite FTS5/trigram + BM25** 的词法检索增强生成，复用现有 Tree-sitter。无 embedding API、向量数据库或新增服务。它通过原生 `rag_search` 工具接入现有 Agent Loop，不替换 `repo_map`、`search` 或 `read_file`。

## 启用与演示

在操作者指定的助手 TOML 中加入：

```toml
[rag]
enabled = true
```

默认关闭。模型不能通过工具开启配置、指定其他仓库或修改索引路径。使用现有 `run` / 在线 `ui` 入口，明确指定仓库、配置和固定验收命令；运行目录必须在源码仓库之外。重启已有服务才能载入新代码和配置。`check-config` 会展示工具是否注册，但不等于索引或真实模型验收。

可用演示任务：“查找配置端口的解析逻辑，引用路径和行号，修复缺陷；修改后重新检索，核对最新内容，并运行固定测试。”现有纯 `--demo` 是固定脚本，不会自动使用这个新增工具。在线模型调用仍使用原有 API Key 入口并产生供应商费用。

模型调用：

```json
{"query": "parse_port validation", "top_k": 3}
```

查询最多 256 字符、16 个字母/数字词；`top_k` 为 1–5。输入作为字面词处理，不接受模型提供的 SQL、FTS 操作符、目录或数据库参数。3 字符及以上的词通过 trigram FTS5 的 OR 匹配与 BM25 排序；仅含短词时使用有界字面子串匹配，结果标明 `literal_short_query`，不伪装成 BM25 得分。混合长短词查询的排名仅使用长词。需要正则或更细粒度定位时继续使用原 `search`。

## 来源与更新

每次成功返回包括：

- `hits`：路径、起止行、符号/标题、正文、完整源文件 SHA-256、`path:start-end` 引用以及分数。BM25 分数越小越相关；短查询回退分数为 0，不用于比较相关性。
- `repository_id`、`base_commit`、`chunker_version`：区分 worktree 与索引格式。`base_commit` 是 Git HEAD；命中内容可能有未提交修改，以文件摘要确认实际版本。
- `updated_files`、`removed_files`、`skipped_files`、`stale_hits_dropped`：本次同步变化和排除情况。`untrusted: true` 提醒模型将结果作为资料。

每次新搜索都重新枚举并计算合格文件的内容摘要；只有变化的文件重新分块/写索引，删除和新变为不合格的文件会移除旧条目。同大小、同修改时间的变动也能检出。没有后台文件监听器；修改发生后，在下一次搜索时更新。运行重启后复用缓存并重新核对，不能仅凭缓存时间戳信任旧内容。

返回命中前再次读取源文件核对摘要，已知过期结果丢弃并从索引移除，下次新请求重建。返回后仍可能发生新的修改，因此编辑前仍需核对当前文件；这不是文件系统快照或事务锁。

原持久化网关会重放相同 operation 的历史结果。补丁后必须发起**新的 operation**，才能取得刷新后的证据；不能把历史轨迹中的旧引用当成当前事实。模型提示词已包含此约束。

## 范围与安全

- 只索引 Git 仓库根内的 Python/Markdown，包括未忽略的新文件；通过 Git 排除规则同时剔除已跟踪但被忽略的文件。有有效 HEAD 的空仓库返回成功的空结果，删除最后一个文件时清空旧索引；没有 Git 根或有效 HEAD 时仍明确失败。
- 排除隐藏路径、依赖/构建/运行数据目录、技能目录和 SKILL.md、敏感名称、符号链接、硬链接、FIFO 等非普通文件、非法 UTF-8 和任意位置含 NUL 的文件。
- 已配置密钥或现有 Redactor 规则命中的文件整个跳过，原文不写入新索引；这不是能识别所有未知秘密的 DLP。只在有权访问的可信仓库上启用。
- 最大 500 个合格文件、10 MB 总文本、单文件 256000 字节；Git 枚举另限 10000 条路径/1 MB 输出。单文件超限跳过；总规模或时间超限则明确失败，不返回部分旧索引结果冒充完整搜索。
- Python 按 Tree-sitter 符号边界分块，Markdown 按标题分块，再切成最多 100 行；解析器不可用时按行退化。返回最多 5 块、正文合计最多 8000 字符，按完整行截断，引用与返回正文一致。超长单行可能无法返回，需使用分页读取工具。
- 索引固定存于 `<runtime>/rag`，私有目录与文件权限，按 worktree 路径/设备/inode 分库；拒绝源仓库与缓存重叠及缓存链接。SQLite 使用事务，进程文件锁串行化同一索引写入；忙时失败，不无限等待。
- 工具总预算最多 10 秒，遵守剩余任务时限。缺少 SQLite FTS5/trigram 时明确失败，模型可改用原有安全检索；不会偷偷联网或安装依赖。
- 仅主编程 Agent 注册此工具，本版不增加分析子代理权限。命中资料不能批准命令、修改 Skills 或绕过既有审批、路径、预算、验收限制。同一用户下的恶意进程仍不属于本项目 OS 隔离能力。

索引是可重建的本地缓存，不是 MySQL 任务数据，不应提交 Git 或公开分发。缓存损坏、格式/身份不匹配时会失败；停止相关任务后，操作者可以备份并移走该专用缓存，再由新搜索重建，不需修改源码或降低安全检查。

## 验证口径

测试使用真实临时 Git 仓库和 SQLite FTS5，覆盖引用、更新/删除/重启、中文/短查询、忽略与敏感内容、源和缓存链接、字节/数量/时间限制、并发锁、FTS5 缺失和检索期间变动。本地 HTTP 合约测试驱动完整编程链路，确认补丁前后检索摘要不同且宿主验收通过；该自动化测试不调用真实 DeepSeek。另已完成真实 DeepSeek + MySQL 仓库任务，8/8 验收及候选全量回归通过，详见 [真实 RAG 验收](LIVE_RAG_VERIFICATION.md)。

当前证明功能与安全边界，不报告未经测量的 Recall@5、MRR、真实模型修复率或费用收益。20–30 题检索质量基准、对比 ripgrep 以及后续 embedding 仍是 [后续评估计划](RAG_DESIGN.md)。排错过程继续记录于 [DEBUG_JOURNAL.md](DEBUG_JOURNAL.md)。
