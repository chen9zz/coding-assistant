# 上下文与项目记忆（Demo）

本版提供完整 HTTP 请求的字符预算、可重建任务检查点、原始工具结果分页读取，以及显式启用的项目记忆。模型不能写入或批准长期记忆；命令、路径、Skills 审批与宿主验收规则不变。

## 上下文分层

每次在线模型请求包含：宿主指令与任务约束、用户目标、历史事实检查点、配对的工具调用/结果。检查点只记录操作数、最近操作、最近失败/拒绝、曾请求审批及成功补丁的操作 ID；每类历史列表有上限。它不生成未经验证的原因分析或下一步计划，也不把历史成功解释为当前代码仍然正确。

`HTTPRuntime.prepare_context` 在网络请求之前计算完整 JSON 的字符数，包括系统指令、工具目录、检查点和历史。超限时复用压缩器，保留最近两轮完整结果，较早结果替换为原始摘要及可移除的短预览。仍放不下则明确失败，不能通过删除宿主约束或工具请求的一侧来凑预算。

这是字符预算，不是模型专用 tokenizer 或输入/输出总 token 限额。供应商的实际 usage、输出预留和按信息价值选择片段仍是后续工作。ScriptedRuntime 继续验证 AgentContext 字符预算，不冒充 HTTP 用量测试。

重复压缩保持最初结果的 SHA-256，不再对压缩摘要本身重新命名；operation ID 和请求/结果配对不变。保留原请求可能导致大补丁参数仍占预算，此时停止而不是篡改执行历史。

## 可恢复检查点与证据读取

持久化工具记录是唯一执行事实来源。恢复任务时从原记录重建上下文，再生成检查点；不另写一份可能与数据库不一致的模型摘要。任务目标和宿主约束始终独立保留。现有操作幂等标识、剩余步数/时限及不确定副作用停止重试策略不变。

新增只读工具：

```json
{"operation_id": "previous-operation-id", "offset": 0}
```

工具名为 `context_read`。每页最多 8000 字符，返回完整原始结果的 SHA-256、`next_offset` 和 `historical_only=true`。它只查当前 worktree 对应任务的已提交结果，不接受 task_id、数据库路径或其他工作区；不允许递归读取 context_read 自己的结果。未提交、缺失、跨任务记录均拒绝。

读取的是已持久化、已脱敏的工具证据，不是模型隐藏推理。修改文件前仍需读取当前源码；历史记忆查询的重放结果不能证明来源现在仍未变化。当前实现只向主任务注册该工具，分析子代理权限不扩展。

## 项目记忆生命周期

数据存于 `<workspace>/memory`，按源仓库规范路径及目录身份分区。原仓库与任务 worktree 共享逻辑作用域，不同克隆默认不共享；不跨用户/仓库自动传播。

| 状态 | 含义 | 模型可检索 |
| --- | --- | --- |
| candidate | 操作者提交、尚未确认 | 否 |
| approved | 操作者确认且当前来源摘要吻合 | 是 |
| retired | 显式停用，保留记录 | 否 |
| stale | 来源变化、删除或被排除，计算出的有效状态 | 否 |
| unverified | 无法扫描来源时，管理列表显示的有效状态 | 否 |
| deleted | 显式忘记，记录从活动存储移除 | 否 |

每条记录包含 ID、标题、正文、来源相对路径、来源文件 SHA-256、状态与时间。确认/停用/删除均需要操作者提供刚查看的完整记录摘要，防止误操作旧版本。正文没有原地覆盖入口：更正时提出新候选；相同标题已有 approved 记录时先显式 retire，不能静默替换。不会自动判断不同标题之间的语义冲突。

确认仅代表用户允许复用这条经验，不证明正文在语义上正确，更不会授予任何工具权限。模型读取时仍收到 untrusted 标记。

来源复用 RAG 的有界文件筛选：仅授权仓库内 Python/Markdown，遵守 Git 忽略规则、敏感路径、二进制、链接、大小和数量限制。检索返回前再次读取来源摘要；每次新 operation 都重新验证。失效不自动改写为新的经验；文件恢复为完全相同内容时可重新匹配。单文件摘要不能感知所有跨文件语义变化。

## 启用与管理

在宿主显式指定的助手配置中加入，重启服务后生效：

```toml
[memory]
enabled = true
```

默认关闭，关闭时不注册 `memory_search`。启用后主 Agent 可调用 `memory_search({"query":"关键词"})`，采用有界字面匹配，每次最多 3 条。没有 embedding、向量库或自动写入工具。

操作者通过 CLI 管理，workspace 必须与在线任务使用的目录一致，repo 是任务的源仓库，不是临时 worktree：

```bash
forgepilot memory propose --workspace /private/tmp/forgepilot-work \
  --repo /absolute/path/to/repository --title '配置入口' \
  --text '修改端口解析前检查缺省值和范围校验。' --source config.py

forgepilot memory list --workspace /private/tmp/forgepilot-work \
  --repo /absolute/path/to/repository
```

查看候选正文、来源、`id` 和 `record_sha256` 后，以实际值执行确认：

```bash
forgepilot memory approve --workspace /private/tmp/forgepilot-work \
  --repo /absolute/path/to/repository --id RECORD_ID --expected-sha256 RECORD_SHA256
```

停用使用 `retire`，忘记使用 `forget`，都要求 ID 与当前记录摘要。来源扫描超限或失败时仍可列出元数据、停用和删除；批准和检索不能绕过来源核验。仓库目录本身仍须存在，以确认身份。forget 不保证抹除操作者已有的备份或历史模型请求。

目录/文件要求属于当前用户、私有权限；拒绝符号链接、硬链接、非普通文件。存储采用标准库 JSON、文件锁、描述符相对访问、临时文件原子替换和 fsync；每仓库最多 64 条、总文件 256 KiB、每条正文最多 2000 字符。选择有界 JSON 是为了避免新增数据库迁移与服务，并非向量记忆库。文本和来源受已有脱敏规则检查，未知秘密仍需人工把关，禁止把密钥写入正文或 CLI 参数。

## 验证与边界

回归覆盖重复压缩摘要稳定、检查点重建、完整 HTTP 请求预算、原始证据跨重启分页、跨任务拒绝、默认禁用、候选确认、摘要冲突、同标题冲突、仓库隔离、修改后失效、返回前二次核验、停用删除、来源不可用时管理、秘密排除与链接拒绝。真实生产 Agent Loop 合约流程：批准记忆→检索→修改来源→新检索排除过期记忆→回读历史证据→宿主验收。

这些是确定性与合约测试，未新增真实 DeepSeek 成绩。没有自动经验提取、模型生成语义摘要、共享跨仓库记忆、可视化记忆编辑或多 Agent 写入。当前原型仍用于个人可信仓库，不是同用户权限恶意进程的 OS 隔离环境。

2026-10-28 验证：后端 425 passed / 5 skipped，启用分支统计的覆盖率 88.63%；Ruff、mypy、前端 12 项测试、类型检查与构建通过。跳过项涉及未启用的真实 MySQL 环境及 SQLite 不适用的 MySQL 行锁测试。
