# RepoPilot-R Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a portfolio-grade issue-to-verified-patch software engineering agent with isolation, safe tools, durable recovery, evaluation, API/SSE, a React dashboard, and evidence-backed documentation.

**Architecture:** A modular Python monolith keeps lifecycle and policy deterministic while model runtimes, Git worktrees, SQLite, telemetry, MCP, and HTTP remain adapters. The same application service powers CLI, FastAPI, evaluation, and the web dashboard. A scripted runtime makes every safety/recovery path reproducible offline; an optional OpenAI Agents SDK adapter supplies real-model execution.

**Tech Stack:** Python >=3.12, Pydantic v2, FastAPI, Typer, SQLite, Git worktrees, ripgrep, Tree-sitter, OpenAI Agents SDK (optional), MCP (optional), OpenTelemetry (optional), React 19, TypeScript, Vite, pytest, Ruff, mypy, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-23-repopilot-r-design.md`

## Global Constraints

- Final delivery root is `/Users/chen/Agent study/project`.
- The source checkout must never be edited; every task mutation occurs in a dedicated Git worktree.
- Offline demo and required tests must need no API key, Docker, network service, or model credits.
- Commands run as argument arrays with `shell=False`, a fixed working directory, an environment allowlist, timeout, and output budget.
- All paths are resolved after symlinks and must remain within the task worktree.
- A model may request a tool but may never bypass policy, set lifecycle state, or execute a side effect directly.
- Tool operation IDs are idempotent across process recovery.
- Default telemetry excludes prompt/file content and redacts known secrets.
- No automatic Git push, pull-request creation, or merge.
- Report only benchmark numbers generated by the delivered verification commands.
- Use `/opt/homebrew/Caskroom/miniforge/base/bin/python3.13` locally; declare Python >=3.12 in package metadata.
- Every source task follows red-green-refactor and ends with a focused commit.
