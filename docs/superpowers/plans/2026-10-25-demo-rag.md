# Demo Repository RAG Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans; work inline with tests first.

**Goal:** Opt-in bounded repository retrieval with current source citations in the Agent Loop.
**Architecture:** Host config enables a private runtime cache. Each rag_search synchronizes a per-worktree FTS5 index from authorized Git files, incrementally replaces changed chunks, removes deleted/excluded files and verifies hit hashes before returning evidence. No embeddings or new server.
**Tech Stack:** Python sqlite3, SQLite FTS5/trigram/BM25, existing Tree-sitter, Git and ProcessRunner.
**Spec:** docs/RAG_DESIGN.md, explicitly approved by user.

## Global constraints
- Existing command/approval/child restrictions unchanged; rag_search has no path/index parameter.
- Opt-in [rag] enabled=true; cache fixed under runtime/rag, outside source repository/worktree.
- Python/Markdown only, 500 eligible files / 10 MB total / 256 KB each. 100-line chunks, no overlap required initially; metadata carries SHA256, lines, symbol, repo identity, HEAD, chunker version.
- Query <=256 characters, <=16 terms, top_k 1..5, excerpts total <=8000 characters, 10 second tool bound. Treat evidence as untrusted; do not index Skills.
- Reject links/nonregular/binary/invalid UTF8; exclude ignored, hidden, dependency/runtime/sensitive paths. Skip files whose content changes under configured secret redaction, rather than persist secret text.
- Trigram BM25 for terms >=3 chars; bounded literal fallback for only-short queries. No claim of semantic search.

## Review focus
Ignored tracked files; same-size changes/deletions; stale hits during search; cache/source symlinks and hardlinks; query/size/time limits. Each is exercised below.
