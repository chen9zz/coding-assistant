# Skills 创建、写入与加载（Demo）

已实现 `skill_list`、`skill_read` 和显式启用的 `skill_write`。原 `skills.roots` 保持只读；新技能保存在独立受控目录，每次创建和更新都走现有持久化审批。没有技能市场、安装脚本、删除接口或权限提升。

## 配置

由操作者在仓库、候选 worktree 和现有只读技能目录之外创建一个专用目录，权限设为 `0700`。不要使用 home、临时目录本身或 Codex/Claude/Agents 的全局技能目录。路径各层不能是符号链接；macOS 的 `/tmp` 是链接，临时演示可使用 `/private/tmp` 下的专用子目录。

```toml
[skills]
roots = ["/absolute/path/to/readonly-skills"]
write_root = "/absolute/path/to/private-forgepilot-skills"
```

未配置 `write_root` 时不会注册写入工具。根目录必须已存在、属于运行服务的用户且无组/其他用户权限；服务不会替操作者自动创建任意根目录。相对配置路径按 TOML 所在目录解释。此实现使用 POSIX 文件描述符和文件锁，适用于 macOS/Linux。

重启运行中的服务才能载入新代码和新配置。`check-config` 可检查技能目录及工具注册；如果同时配置了 MCP，它会启动相应 MCP 程序，不调用模型，也不能证明 API Key 有效。密钥仍通过原有隐藏输入流程注入进程，不写入本文示例或 TOML。

## 操作闭环

1. 模型调用 `skill_list({})` 刷新元数据并取得 `root_id`。加载仍是元数据→正文→引用的按需流程。
2. 创建时调用 `skill_write`，必须提供 `name`、`resource`、`content`、`root_id`、`expected_sha256` 五个字段。`expected_sha256: null` 表示目标必须不存在。
3. 网关校验目标后暂停，界面显示确切路径、内容差异和请求参数。操作者批准该 operation 才执行；拒绝或未批准不会写入技能内容。
4. 更新前用 `skill_read` 逐页读完文件，使用返回的完整文件 `sha256` 作为 `expected_sha256`；再进行一次独立审批。等待期间内容变化会拒绝覆盖，必须重读并重新请求。
5. 创建成功后 `skill_list` / `skill_read` 自动刷新，无需重启；重开会话也会重新扫描该目录。

合法的初始正文示例（目录名必须是 `regression-repair`）：

```markdown
---
name: regression-repair
description: 先复现仓库缺陷，再实施小范围修复并运行固定验收。
---
先定位失败用例及相关实现。写出能复现问题的测试，再修改实现。
不得绕过宿主审批、固定验收命令或任务预算。
```

仅允许 `<write_root>/<name>/SKILL.md` 和 `<write_root>/<name>/references/<filename>.md`。名称为小写字母、数字及连字符，最多 64 字符；引用文件名只接受字母、数字、下划线、连字符及 `.md` 后缀，不能有额外目录层。先创建合法的 `SKILL.md`，再单独审批引用文件。每个文件最多 65536 UTF-8 字节，技能总数最多 64，读取每页最多 8000 字符。

## 安全与恢复

- 审批绑定 operation、完整参数摘要、根目录身份、旧内容摘要及新内容；修改内容或更换根目录不能复用原审批。
- 拒绝目录穿越、绝对资源路径、符号链接、硬链接、非普通文件、NUL 和非法 UTF-8；已有只读技能不可覆盖或同名遮蔽。受控根目录只读取上述 Markdown 资源。
- 写入以根目录文件锁串行化，使用私有临时文件、同步和原子替换。已提交结果直接回放，不重复落盘；持久化结果不确定时保留原有停止策略，不盲目重试。
- `.write.lock` 和写入过程中的 `.pending-*` 是内部实现文件，不是模型可指定的写入资源；中断可能遗留临时文件，不能将其当成技能加载。
- Skills 是不可信任务资料，正文或 `allowed-tools` 不赋予权限；只读分析子代理只获得列表/读取能力，没有写入工具。
- 原命令、路径、预算、审批及宿主验收不变。这不是 OS 级恶意代码沙箱，同一用户权限下的任意宿主程序仍在原威胁模型之外。

当前任务入口仍面向代码仓库修复，要求产生补丁并通过固定测试。因此演示应使用“完成仓库修复，同时经审批保存可复用技能”的任务；单独保存技能并不意味着整个编程任务能通过最终验收。没有新增独立技能编辑页面。

## 验证与排错

集成测试覆盖审批前无写入、创建/更新/引用、摘要冲突、根替换、链接及 FIFO、只读冲突、锁竞争、参数变化、同会话加载和重启恢复；完整闭环在持久化暂停后重开服务，批准技能创建，重新读取技能，修复 fixture 仓库并通过宿主验收。模型由确定性运行时替代，不冒充新一轮 DeepSeek 实测。

遇到拒绝时检查目录权限、路径是否经过链接、资源类型及摘要。不要把拒绝策略改成允许：重读最新内容并提交新的审批。详细调试过程见 [DEBUG_JOURNAL.md](DEBUG_JOURNAL.md)。
